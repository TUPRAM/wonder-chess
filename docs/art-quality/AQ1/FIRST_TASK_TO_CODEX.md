## Phase A — Baseline and safe candidate

Inspect the actual `.blend` and MCP tool capabilities. Confirm whether the screenshots match the current source. Save/hash a before-copy; do not overwrite the canonical source. Record mesh and material statistics from the loaded asset, not from an old manifest alone.

Capture matched clay and material views, face and grip closeups, and normal gameplay framing. Diagnose the three largest visible problems. Do not infer missing materials from solid viewport mode.

Prove that you can obtain and inspect a real screenshot. Use fixed-camera saved renders when the viewport is too small for a useful comparison. Keep scripts within the actual tool permissions.

## Phase B — Choose a visual direction

Produce three limited silhouette/proportion candidates matching the directions in the Ada brief. Use an available approved image tool or rough Blender studies; label the method accurately. Do not copy competitor characters.

Present actual comparable views and a short recommendation. Ask Pram to select the direction before detailed production. During that approval boundary, complete non-destructive independent checks but do not mass-produce an unapproved style.

## Phase C — Rebuild major forms

Work on the selected candidate. Prioritize the head/neck, coherent torso/limb transitions, curved shoulder construction, convex shield, forged blade cross-section, and integrated palm/fingers/thumb. Then refine the coat, tabard, boots, and material boundaries.

Do not preserve the old 112-vertex head shell merely because an old script expects it. Do not run count-based component deletion on a new topology. Migrate candidate tools to stable semantic parts.

Do not run `author_alpha.py --all` or reset the live scene as an incremental polish operation. The base generator is a reconstruction/blockout route, not an approved artist source.

Do not use indiscriminate subdivision, smooth shading, or blanket decimation as the only solution. Make each large form convincing in clay before adding tertiary detail.

After each meaningful change, inspect the actual render, record the biggest remaining defect, then revise or revert. Evidence and status must describe what happened, not what the code intended to do.

## Phase D — Surface and animation integration

Author useful UV coverage and materials. Replace flat placeholder normal content where actual baked detail is required. Preserve intentional simplicity on low-priority surfaces. Keep geometry and texture budgets explicit; exceptions need comparison and approval.

Keep rig compatibility when sound. If approved proportions need a rig revision, isolate it and retarget/review rather than concealing differences in scale. Test all seven clips continuously and at contact/extreme poses.

## Phase E — In-engine proof and acceptance

Import into a candidate Unreal location. Verify unit/axis conversion, normals/tangents, material behavior, animations, sockets, bounds, and actual board-camera readability. Perform a crowded-fight capture and a deliberate source change/reimport. Preserve gameplay timing.

Provide matched before/after views, actual runtime evidence, outstanding issues, measured cost, and an honest status. Pram must approve the reference character before any bulk art rollout. Do not approve it yourself using a numeric score.
