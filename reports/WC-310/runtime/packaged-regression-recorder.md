# Packaged regression evidence update

The root-authorized change to `AWCMatchMode::Regression` was saved and frozen after candidate4. Its source SHA256 at handoff is `4a71a0deaa7689004cf09237ff67cf7aa09c8c9a49de2773a70642a61e96831f`. The source has not yet compiled or executed at this checkpoint. No combat decisions, canonical values, bot policies or normal gameplay commands changed. Two required includes were added and BeginPlay's redundant normal exit was removed because Regression now sets the actual outcome status.

The runner now honors `-WCEvidenceDir=<path>`, writes an initial incomplete report, retains every attempted trial as it finishes, and writes final completion metadata. The process requests exit0 for a completed failure-free run, exit1 for failed trials, and exit2 for evidence-write failure. A caller must still inspect the JSON and actual process status; termination/crash or an unavailable output path can leave a partial or absent report.

Each trial records start/endUTC, simulation steps, invariant-check count, final phase, cap state, actual bot command/rejection counts and reasons, unresolved encounters, total fights/timeouts/ghosts, match and fight durations, survivors, final placements, and each round's settlement ID/state hashes and seat health/gold/damage/wins/placements. Hashes use strings so JSON does not round64-bit values. Existing seed/error/pass fields remain.

At each actual preparation-to-combat transition, the observer records living seats' deployed owned units once, before the fight advances. It derives per-seat/per-hero deployment unit-rounds, distinct owned instances, rounds present and maximum deployed star, tied to final placement. Duplicate copies count separately in unit-rounds and once in rounds-present. Eliminated rosters and copied ghost ownership do not inflate use. These are descriptive use/placement observations, not causal balance estimates.

The report records engine/schema/balance versions, profile ID, CPU, executable path, MSVC compiler macros and this translation unit's compile date/time. It computes actual SHA1 values of the loaded staged rules/units/traits/bots/world files and manifest. The staged SHA256 is copied only when that entry's SHA1 matches the loaded bytes. The installed `FGenericPlatformMisc::GetSHA256Signature` implementation asserts that it is unimplemented; it was therefore not used. This dual-hash provenance is explicitly described in the report and does not pretend a manifest SHA256 was recomputed in engine.

Available current C++ source files are hashed separately and labeled observed at runtime. Such files may be absent in a distributed package or changed after compilation. The external build/package wrapper must still hash the actual executable, delivered package and compiled source snapshot and retain toolchain response files/commit when available. Simulation timing includes evidence collection and remains separate from rendered frame-time profiling.
