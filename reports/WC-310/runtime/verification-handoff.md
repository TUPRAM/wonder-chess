# Integrated verification recorder handoff

This document describes implemented instrumentation, not an executed packaged/network acceptance result.

`game/Source/WonderChessRuntime/Private/WCVerification.cpp` records actual local controller state when enabled by `-WCExercise`, `-WCProfile`, or `-WCShots`. The latest optional authority probes and takeover sampler compiled and linked in `reports/WC-350/candidate3-editor-retry.log` (48.20seconds, Result:Succeeded). Recorder source timestamp14:19:56 precedes that completed build at14:22:40 local time on2026-09-06. Actual packaged probe execution remains a separate gate. A subsequently added asset-test assertion comparing persisted skeleton and mesh reference roots is frozen for the next combined build and is not covered by candidate3.

Each process should use its own absolute `-WCEvidenceDir=`. It saves `session.json` for the latest match plus match-namespace/seat/PID-prefixed session summaries, complete received public and owner-private snapshots every 500 wall milliseconds, phase/round transitions, actual reply/probe events, screenshots, and frame CSV rows. Match namespace changes reset recorder state without overwriting the prior match's files.

`-WCExercise` submits commands through actual human controller authority. It probes an invalid sequence, a valid shop-lock request, the exact duplicate and changed payload under the same request ID, waiting for actual replies and owner-private acknowledgement. The script restores the original unlocked shop through a normal command, then uses legal purchases/deployment/XP/reroll/ready. It never supplies combat outcomes. This is automated input through human player bindings; it does not establish human usability or enjoyment.

`-WCRestartOnce` with the exercise waits two wall seconds at first results and has the actual host send `ServerStart` once. The second namespace is allowed to finish without another automated restart. Persistent network abort state prevents automatic restart/start after host loss. Actual completion of both namespaces must be verified from saved reports/logs; the switch alone is not evidence.

`-WCProfile` begins sampling five wall seconds after each namespace starts. It records frame interval, game/render active time, nonzero `RHIGetGPUFrameCycles` samples, named CPU, active RHI adapter, OS primary GPU, engine, render settings, viewport dimensions, observed process memory, visible/logical living unit counts and active encounter counts. `-WCFast=N` is recorded and must be disclosed for accelerated runs. GPU zero values are unavailable samples, not zero-cost rendering. Timings include instrumentation overhead and remain scoped to the observed viewport.

Run the evidence readers only on actual exports:

```powershell
python tests/runtime/audit_network_evidence.py '<host-session.json>' '<client-session.json>' --require-complete --output '<paired-audit.json>'
python tests/runtime/summarize_frame_evidence.py '<session.json>' --output '<frame-summary.json>'
```

The paired audit checks distinct process IDs, host/client roles, two human seats and six bots, owner-private seat binding, received public privacy, real probe responses, matching pairings/combat tick states/settled standings, and complete final results. It records source file hashes. It does not certify packet capture, hostile-client resistance beyond exercised commands, simulated latency/loss, disconnects or rejoin handling. Those need separate actual execution.

The frame reader separately selects frames with twelve visible living units and four simultaneously live encounters. If that subset is absent, the required busy load remains `NOT_RUN`. A smaller combat or a later two-encounter fight is not silently substituted. Viewport 1920×1080 is checked separately; actual render scale remains in the recorded settings.
