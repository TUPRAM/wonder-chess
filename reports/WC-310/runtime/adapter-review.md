# Read-only adapter review, 2026-09-06

Scope: `WCMatchRuntime.cpp`, `WCVerification.cpp`, `WCBoardPresenter.cpp`, and the connected HUD command path in `WCMatchHUD.cpp`. Source hashes for this reviewed snapshot are in `adapter-review-snapshot.json`. Findings were sent to the integration owner for fixes; this is not a claim about any later corrected build. The runtime lane did not edit these files.

| Priority | Finding in reviewed snapshot | Recommended integration fix |
|---|---|---|
| P1 | `ServerIntent` authenticates a numeric seat but does not require that seat's current binding to be human. The local 0H8B observer receives bot 0's private shop/economy and can submit commands for it. | Reject human RPCs for bot-bound seats; send only public observation to all-bot spectators. |
| P1 | `Intent` derives sequence and revision from the latest received snapshot for every input. Two rapid clicks before a new snapshot submit the same next sequence; the second requested action is rejected. | Maintain an acknowledged command queue or one in-flight operation with buffered intentions. Preserve request IDs for genuine retries. |
| P1 | During a tournament `Logout` preserves weak controller array entries. A later restart checks array length, so a disconnected second controller can count as a live human and create a human seat with no controller. | Count valid connected bindings and require a fresh lobby before another 2H6B match after takeover. |
| P1 | No explicit client network-failure path aborts the displayed match when the host disconnects. | Handle host loss by showing an aborted/no-winner result, with no host migration or rejoin claim. |
| P2 | `LastEventTick` resets only when the encounter index changes. The same index often persists across rounds, suppressing new-round combat audio until the new tick passes the old maximum. | Reset presentation event history on round or match-namespace change. |
| P2 | Unit hitboxes exist only for editable own preparation formations; opponents and combat units cannot be inspected. Inspection displays base one-star values even for an upgraded selected instance. | Separate inspect actions from placement ownership; show actual star/trait-derived values and distinguish current buffs from nominal base values. |
| P2 | The Ready button switches to the `match.unready` label, but the command only sets readiness true. | Use a truthful ready-state label or implement an explicit validated unready intent. |
| P2 | The verification harness keeps `Complete`, screenshots already taken and profiling arrays when the same controller starts another match. | Start a new evidence session on match namespace change so restart evidence cannot reuse old completion. |

Checks that were satisfactory by source inspection: public seat serialization contains public deployed formations and omits private bench fields; private state travels through a client RPC on its owning controller; the server determines command prices and outcomes; no client path writes combat results. Combat IDs namespace encounter and side, remain below the exact-integer limit of JSON double representation in the 24-round alpha, and do not collide with persistent preparation unit IDs. The ghost donor's owned resources are not duplicated or altered by its combat clone. These observations support targeted tests but do not replace actual network capture and two-process execution.
