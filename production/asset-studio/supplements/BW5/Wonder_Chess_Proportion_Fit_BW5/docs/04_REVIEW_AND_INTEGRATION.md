# 4 — What constitutes a useful delivery

## Do not conflate outcomes

Record these independently:
- **PROPORTION_REVIEW:** projected reference relationships and overall silhouette.
- **LOCAL_CONSTRUCTION:** coherent editable shell/hand, openings, thickness, interfaces and no confirmed blocking geometric defect.
- **AUTHORING_MOTION:** named action and sampled pose coverage; not runtime.
- **RUNTIME_CANDIDATE:** actual game skeleton, imported assets, seven actions and relevant transitions.
- **HUMAN_FORMS_APPROVAL:** external human decision, never self-issued.

A new ratio is not a likeness score. A clear intersection query does not approve a floating shell. A good source render does not certify game import.

## Required armor evidence

1. Freshly source-bound frame1 front/back/sides/three-quarter against BW4, using matching cameras and unchanged reference pose within each pair.
2. Separate normalized reference-comparison views with recorded body anchors, pose, camera type and scale. Do not relabel these as the original BW4 views.
3. Native source artwork and annotated measurements; exact endpoint corrections and uncertainty if changed locally.
4. Actual cage views plus section views through neck, chest, lower ribs, waist and armhole conflict regions.
5. Body, padded coat and inner/outer plate identified independently. Record gap and projection at each section, with units.
6. Rest, earliest crossing and worst conflict samples for the back/cap/lowest lame. Include low-arm reference-like posture, not just raised-arm clearance.
7. Full 97-frame authoring recording with native inputs, frame rate, source hash and action name. Additional critical subframes are geometric evidence; state their coverage.
8. Assembled full-body context at gameplay/gallery-relevant framing, with unchanged head/hair/opposite/leg/bracer parts identified as context until actually replaced.

The earlier report's zero front/first-lame transverse crossings must be rerun after any influencing garment/attachment/shape change. No source finding survives an altered dependency automatically.

## What must not be hidden

Do not lower the arm range, omit the failing frames, delete padding, suppress relevant objects in collision queries, or move the camera until the unwanted depth disappears. Visual isolation is useful only when the complete assembly is also tested.

No all-parts global inflation, all-vertices smoothing, global body shrink, increasingly thick belts/cuffs hiding gaps, or extra detail before shape. Contact tolerances must have fixed units and be reported separately from real penetrations.

Legacy query limits still apply: BVH candidates need the existing confirmation stage; transverse pair tests do not establish all containment/coplanar cases; discrete samples are not a continuous-time proof. Group reported pairs by localized component/region so topology density does not masquerade as a severity score.

## Runtime path after local success

Maintain separate authoring and export candidates. Inspect actual material slots, skeleton names, rest/bind matrices, sockets and ownership in the current project. Do not replace source body topology or the shared 27-bone skeleton to simplify a new derivative.

Rigid-looking plate behavior needs a verified runtime representation. Authoring helpers/constraints may be baked to supported animation or require an explicitly reviewed rig extension. A Blender driver or MPFB joint is not automatically present in Unreal.

Unreal sockets support bone-relative attachments and mesh-specific sockets for some shared-skeleton cases (B6). Any candidate attachment remains isolated until its visual and motion behavior is verified. Never edit the shared skeleton asset as a hidden side effect of testing one glove.

Run all seven actions in the actual integration candidate and test transition frames. Verify rest stance, shield raise, sword swing, moving arms, hit interruption, defeat and restart/replay. Read actual clip data; do not assume identically named MPFB actions are compatible.

Import/reimport and package checks only happen when the relevant local geometry is viable and tools are present. The person performing this task must record actual results. A missing integration capability can leave a credible AUTHORING_ONLY candidate; it cannot justify an invented runtime pass.

## Workflow size and priorities

Give armor the first lane. Separate hand source/ownership. Reuse existing tools and the supplied records/illustrations rather than building a new system around BW5. Do not add a new approval service, train a model, download a replacement character, or rewrite gameplay.

At an early checkpoint, the before/after must already show the altered chest profile/plate height/collar relationship. If it only looks smoother, the task is drifting.

An initial construction plus two substantive non-improving revisions is a method review limit. Intermediate selections, hypothesis renders and accepted local edits are not each a new full trial. Do not produce an endless chain of nearly identical revisions or reset limits with a renamed workstream.

On failure, retain the exact candidate and one concise intervention brief. Keep independent game and costume work moving. Human review may choose a development-use candidate while explicitly retaining art debt; never fabricate that decision.
