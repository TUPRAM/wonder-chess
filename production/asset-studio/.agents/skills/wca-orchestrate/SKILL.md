# wca-orchestrate

## Inputs and scope

Read the repository instructions, `production/asset-studio/docs/00_SYSTEM.md`, the active asset manifest, current source and direct gate dependencies. Confirm ownership and actual tools. Do not load every manual or modify unrelated gameplay.

## Procedure

1. Inspect existing repository instructions, working tree, current canonical asset and pending local revisions. Preserve stable IDs and gameplay behavior.
2. Discover actual image-generation/vision, Blender MCP, local script and Unreal capabilities. Record real responses and path mappings, not assumed integrations.
3. Choose asset kind and route from config/routes.json. Initialize an isolated candidate workspace only when missing; inspect state and evidence before resuming.
4. Identify the first pending or stale gate. Read only its skill/manual and direct input contracts. Assign one owner for the asset/session and independent review of actual outputs.
5. Delegate bounded component work only after interfaces and dimensions are agreed. Stop at human reference/forms/release gates without inventing approval.
6. Track two no-improvement attempts and escalate a failed modeling method. Do not substitute file count, more detail or new lighting for corrected forms.
7. Prepare a review packet, run applicable tools, record actual evidence and return next unblocked operation. No background promises.

## Tools and evidence

Use real existing Blender/Unreal/image/audio tooling only after capability discovery. The included ledger, image helper and Blender scripts are documented in `production/asset-studio/docs/07_TOOLS_AND_COMMANDS.md`. They are not replacement modeling intelligence. Capture source hashes, actual images/video/audio, commands and limitations. Do not treat tool success as human approval.

## Outputs and exit

Asset manifest, capability audit, route, isolated workspace, operation log and current gate status.

Prepare a pending report with `assetctl.py report-template`, populate it from real work, and seal with `prepare` only when required observations exist. Obtain the gate’s prescribed reviewer role. Do not invoke human approval yourself. A missing editor or poor required visual result blocks the affected stage.

## Failure and rollback

Do not overwrite canonical assets. Restore/reuse immutable checkpoints; inspect post-timeout state before retry. Record critical/major defects without relabeling them minor. Two no-improvement attempts require a method review or focused human intervention. End with exact next unblocked work, not an unsupported completion claim.
